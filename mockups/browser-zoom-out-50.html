现在 − 在 100% 就灰掉了，因为缩放下限是 1（等于 fit）。三帧：A 现状（100% 是硬底）、 B 新增的 75%、C 新下限 50%。下方还有档位阶梯与改动点。

根因（已核实，非猜测）：
ai-critic-react/src/v2/mcc/screen/viewport.ts:11 → MIN_ZOOM = 1，而 clampZoom() 把 zoom 夹在 [MIN_ZOOM, MAX_ZOOM]。phoneZoom.ts 的档位 PHONE_ZOOMS = [1, 1.25, …] 也从 1 起， 所以 prevPhoneZoom(1) 返回 null → − 置灰。

改动点（before → after）

层现在之后
mcc/screen/viewport.ts MIN_ZOOM = 1；clampZoom() 夹到 [1, 6] 下限参数化：clampZoom(zoom, min = MIN_ZOOM)；浏览器侧传 0.5。Screen 页行为不变
viewport.ts 的 clampView / zoomAt / scaleOf 内部各自调 clampZoom(view.zoom)，无法低于 1 同样接收可选 min 并透传；默认值保持 1，故 RemoteScreen 一行不改也不受影响
browser/phoneZoom.ts PHONE_ZOOMS = [1, 1.25, 1.5, 2, 2.5, 3, 4, 6] [0.5, 0.75, 1, 1.25, 1.5, 2, 2.5, 3, 4, 6]
browser/browserView.ts transformOf / settleView 调 clampView(g, view)，会把 0.5 夹回 1 传浏览器下限，否则"已缩到 50% 但画面仍是 100%"
browser/useBrowserZoom.ts（捏合 / 双击） clampZoom(target) 传同一下限，捏合也能到 50%；双击仍是"在 fit 与 2x 之间切换"
browser/browserZoomPad.ts（触控板） clampZoom(view.zoom * ratio) 同上
− 按钮禁用条件 prevPhoneZoom(zoom) !== null；100% 时为 null 逻辑不变；档位表加入 0.5/0.75 后，只有 50% 时为 null

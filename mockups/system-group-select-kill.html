组详情：点 bar 只折叠；Select 只勾顶级；批量 Kill 仍分 Graceful / Force

页面 /home/system/group/Google Chrome。两件事： （1）点顶级卡片的主体必须是收起/展开，进 pid 页只走右边树标——和 /home/system 组条同一套。 （2）加 Select 模式，只勾 depth=0 的 root，Select all / Unselect all，再批量 Kill，弹窗仍是 Graceful / Force。

结论：浏览态 bar = ghead 折叠，gtree 进 pid 页，kill 在树标左边。 点 Select 后，每个 root 卡片左边多一个勾选框；点卡片主体改成勾选，不再折叠（折叠仍可用 Expand/Collapse all）。 子进程没有勾选框。Kill N 打开现有 kill 弹窗的批量版，对每个未保护 pid 循环调用现有 POST /api/server/processes/kill。

复用现有 SystemKillModal 的模式切换，标题/命令改成 N 个 pid。 客户端按顺序调现有单 pid kill，不新开批量 API。失败的 pid 留在选择里并报错。

规格

项目现在改后
点顶级 bar 源码：ghead → onToggle。线上若仍进 pid 页，是点到了 gtree 或跑着旧包 锁定：主体只折叠。树标才进 /home/system/pid/:pid。Select 模式下主体改成勾选
Select 入口 无 一行、不换行：浏览 = Expand all / Collapse all + 右端 ☐ Select。选中 = Select all / Unselect all + 右端 ☑ Selecting。Kill 是下面一条通栏按钮，不是芯片
勾选范围 — 仅 depth === 0 且未 protected 的 root。子行永不出现 checkbox。Select all 只覆盖当前过滤可见的这些 root
Select 时点 bar — 切换该 root 的勾选，不折叠、不导航。进入 Select 后 Expand/Collapse 让位给 Select all / Unselect all；要折叠先退出 Select
批量 Kill 只能一行一个 kill 弹窗 Kill N 打开同一套 Graceful / Force。对每个选中 pid 调 killHostProcess(pid, signal)。不新开服务端批量接口
状态 — 全是 React state：selecting boolean + selected: Set<pid>。退出 Select / 过滤变化时丢掉已不可见的 pid。不落盘
不建议：
  • Select 勾到子进程：用户明确只要顶级列表。
  • 新开 /kill-batch API：现有单 pid 接口够用，失败可以逐个报告。
  • Select 时把树标也藏起来：进 pid 页和单杀仍要可用。
  • 点 bar 进 pid 页：和 /home/system 组条语言冲突，也是这次要修的错。
